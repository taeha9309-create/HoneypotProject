# 허니팟 공격 분석 대시보드 (Streamlit, MVP)

서울·시드니 Cowrie 허니팟(SSH·Telnet) 로그를 모아 **"지금 상황 → 무엇을 해야 하나 → 근거"** 순서로 보여 주는 관리자용 대시보드다.
기획: [docs/dashboard-plan-v2.ko.md](../docs/dashboard-plan-v2.ko.md). handoff 브랜치의 `dashboard/`(HTML 서버)와는 별개이며 그쪽의 지도 자산(`dashboard/assets/world.json`)만 쓴다.

## 화면 (5개)

| 화면 | 답하는 질문 | 내용 |
|---|---|---|
| **Overview** (상황판) | 지금 상황은? 무엇을 해야 하나? | 상황 등급(위험/주의/안정)과 이유, **지금 할 일**(1순위 차단 IP·다운로드 서버·파일 해시·Telnet 점검·비밀번호 금지 목록), 새로 나타난 것(최근 7일 또는 선택 기간), 규모 KPI(직전 기간 대비), 허니팟 비율·IP 집중도, 접속 추이(프로토콜/허니팟), 출발 국가 지도(IP/세션, 하루 재생), 위험 행동 Top, 인증·수집 파일, 반복 접속 IP, 최근 명령, 허니팟 상태, **보고서 내려받기**(Markdown) |
| **세션 조사** | 이 세션·IP·파일은 무엇을 했나? | **세션**: 필터·목록, 한눈에 보기(요약 문장·공격 단계 칩), 시간순 흐름, 탐지 근거(S01·S02). **IP**: 인증 시도·비밀번호 종류·첫 성공까지 시도 수(무차별 대입 순 정렬), 일별 활동, 세션·행동·계정. **수집 파일**: 해시별 목록, 관측 세션, 다운로드 실패 |
| **탐지 분석** | 어떤 공격 행동이 어디까지 갔나? | KPI, 진행 단계(세션별 가장 깊이 간 단계), 최근 위험도 높음 세션, 위험도 순 행동 목록(규칙·ATT&CK), 행동 상세(설명·일치 입력·세션), 추가 분석(S01·S02 흐름 대상 / 규칙 미해당 입력 / 캠페인) |
| **패턴 분석 (ML)** | 비슷한 공격은 어떻게 반복되나? | 서울+시드니 합본 군집(팀의 `ml/cluster.py`), 군집 지도, 자동 이름, 군집 상세(대표 흐름·행동·다운로드 서버·일별·세션), 신규 패턴 후보 |
| **위협 정보 (IOC)** | 무엇을 막고 점검해야 하나? | 우리 환경 점검 포인트, **차단 후보 IP**(1순위 즉시·2순위 검토·3순위 관찰), 다운로드 서버, 파일 해시, 공격 계정(비밀번호 금지 목록 TXT), 서울·시드니 공통 IP. 모두 CSV 내려받기 |

## 실행

### 1) 설치 (처음 한 번)
```sh
python -m venv .venv
.venv/Scripts/python -m pip install -r streamlit_app/requirements.txt -r ml/requirements.txt
mkdir work/geo   # 국가 조회 자료 (DB-IP Country Lite, CC BY 4.0)
curl -L --fail https://raw.githubusercontent.com/sapics/ip-location-db/main/dbip-country/dbip-country-ipv4.csv -o work/geo/dbip-country-ipv4.csv
```

### 2) 데이터 만들기 (로그를 새로 가져올 때마다)
```sh
.venv/Scripts/python streamlit_app/build_db.py \
    --seoul-logs <서울 Cowrie 로그 폴더> \
    --syd-db data/syd_20261109/honeypot.db \
    --geo work/geo/dbip-country-ipv4.csv --ml
```
결과는 `data/dashboard/`(git 제외)에 생긴다. 원본 로그와 입력 DB는 읽기만 한다.

| 파일 | 내용 |
|---|---|
| `seoul.db` | 서울 원본 로그를 `ingest.py`로 새로 적재 |
| `syd.db` | 시드니 DB 사본 |
| `dashboard.db` | 인증·파일 이벤트, 현재 규칙으로 다시 계산한 탐지, S01·S02 흐름 대상, 국가, 시간별 이벤트 수, 출처 정보 |
| `ml.db`, `ml_out/`, `ml_models/` | `--ml`: 서울+시드니 합본 군집 (팀원의 `ml/out`, `ml/models`는 건드리지 않음) |

### 3) 실행
Windows: 저장소 루트의 `start-streamlit.cmd` 실행. 또는
```sh
.venv/Scripts/python -m streamlit run streamlit_app/app.py
```
브라우저에서 http://localhost:8501 . 처음 열 때 데이터를 읽느라 수 초 걸리고, 이후 조작은 1초 안팎이다.

## 기준 (기획서 4·5·9절 요약)

- **시간**: 화면·필터는 KST, 기간은 시작일 00:00 이상 ~ 종료일 다음 날 00:00 미만. 세션=시작 시각, 명령·인증·파일=발생 시각, 탐지=규칙 최초 일치 시각.
- **제외**: 테스트 접속(`excluded=1`). 인증·파일 이벤트는 세션·시간·IP가 맞는 것만.
- **미수집**: 원본 로그가 없는 출처(시드니 사본)는 인증 실패·파일 실패·수집 공백을 0이 아니라 "미수집"으로 표시.
- **위험도**: 높음=감염·장악·흔적 삭제(S01·S02·B04·B05·B06·B07·B12·B13·B15), 중간=파일 들여오기·실행 시도·비밀번호 변경, 낮음=셸 진입·정보 수집. **우선 확인 세션 = 위험도 높음 행동이 나온 고유 세션**(모든 화면 동일).
- **차단 후보**: 1순위 내려받아 실행·다운로드 시도·흔적 삭제 등 / 2순위 다른 악성코드 종료·무차별 대입(인증 50회 이상) / 3순위 반복 접속만.
- **상황 등급**: 위험=새 다운로드 서버·내려받아 실행·새 파일 해시 중 하나라도 / 주의=위험도 높음 행동이나 새 위험 IP / 안정=그 외.
- **설명과 탐지 분리**: 쉬운 설명은 화면용이다. 근거가 "규칙 일치"일 때만 탐지이고 "입력 기반 추정"은 탐지 건수에 넣지 않는다.

## 보안·표시 원칙

- 공격자 입력은 실행하지 않고, HTML에 넣을 때는 모두 escape한다. URL은 `hxxp://`로 바꿔 링크가 되지 않게 한다.
- IP는 목록에서 `a.b.x.x`로 가리고 상세에서만 전체를 보인다. 예외: 위협 정보(IOC)는 차단 목록용이라 전체 IP를 보인다.
- 외부 조회(VirusTotal 등)는 자동으로 하지 않는다. 국가는 오프라인 DB(DB-IP)로 추정한다.
- 대시보드는 로컬(localhost) 실행용이다. 외부 공개 시 인증을 따로 붙인다.

## 알려진 한계

- 탐지는 **입력 관측**이다. 실제 실행 성공·악성 여부는 확인하지 않는다.
- 시드니 데이터는 11-07까지의 DB 사본이라 원본 로그 기반 항목(인증 실패 등)은 미수집이다.
- 군집 번호는 이 학습 실행에서만 의미가 있다. 다시 학습하면 번호와 자동 이름이 바뀔 수 있다.
- 마지막 수집일은 하루치가 다 들어오지 않아 변화율이 낮게 보일 수 있다(화면에 안내).
