# ML 공격 행동 군집화 결과 (syd, 2026-11-07 기준)

세션별 명령어 시퀀스를 정규화한 뒤 TF-IDF + HDBSCAN으로 군집화한 결과다.
숫자는 모두 아래 재현 명령으로 다시 만들 수 있다. 원본 로그·DB·결과 CSV는 저장소에 올리지 않는다.

```sh
python ingest.py data/raw/syd --db data/honeypot.db
python match_signatures.py --db data/honeypot.db
python ml/cluster.py fit --db data/honeypot.db           # ml_clusters, ml/out/*.csv, ml/models/
python ml/analysis/stability.py --db data/honeypot.db    # ml/out/stability*.csv
python ml/analysis/attack_units.py --db data/honeypot.db # ml/out/attack_units*.csv
```

## 2. 정규화 규칙 (버전 3)

원문(`commands`)은 건드리지 않고 정규화 결과만 따로 만든다. 순서대로 적용한다.

1. 한 입력 줄을 `;`, `&&`, `||`, **줄바꿈**에서 나눈다. 파이프 `|`는 유지한다(셸 파서가 아니라 따옴표 안도 나눈다).
2. URL → `<URL>`
3. `echo "user:비번" | chpasswd`의 비번 → `<PASS>`
4. IP(포트 포함) → `<IP>`
5. 대·소문자·숫자가 섞인 40자 이상 base64 → `<B64>` (`/`로 시작하는 토큰은 경로로 보고 제외)
6. 16자 이상 16진수 → `<HEX>`
7. 같은 세션에서 URL로 내려받은 파일 이름이 다시 나오면 → `<FILE>`
8. 경로 속 8자 이상 영숫자 혼합 이름 → `<FILE>` (`/dev/`, `/sys/`, `/proc/` 아래는 제외)
9. 독립된 숫자 → `<NUM>`, 연속 공백은 하나로

버전 2에서 `/dev/` 장치명과 `/`로 시작하는 긴 경로가 잘못 바뀌던 것을 고쳤고, 버전 3에서 줄바꿈 분리를 추가했다.
규칙을 바꾸면 `NORMALIZE_VERSION`을 올리고 fit을 다시 해야 한다(`assign`이 버전 불일치를 거부한다).

## 3. 방법 비교와 최종 설정

Telnet 1,401세션은 정규화 후 고유 시퀀스가 26개뿐이다(같은 봇이 같은 명령을 반복).
같은 시퀀스는 한 점으로 합치고, HDBSCAN은 세션 수만큼(최대 50개) 복제해 세션 단위로 학습한다.

| model | params | 군집 | 노이즈 | 실루엣 |
|---|---|---:|---:|---:|
| **hdbscan (최종)** | mcs=10, ms=10 | 6 | 0.8% | 0.465 |
| hdbscan | mcs=10, ms=1·5 | 5 | 0.6% | 0.367 |
| hdbscan | mcs=25, ms=25 | 4 | 2.4% | 0.576 |
| hdbscan | mcs=25·50, ms=1·5 | 4 | 1.4% | 0.393 |
| hdbscan | mcs=100 | 0 | 100% | - |
| hdbscan_uniq | mcs=5·10·20 | 0 | 100% | - |
| hash | - | 11 | 1.1% | - |
| dbscan | eps=0.3 | 10 | 0.9% | 0.325 |
| dbscan | eps=0.5 | 9 | 0.4% | 0.385 |

- 정의: 노이즈 비율은 세션 기준. **해시는 세션 1개짜리 시퀀스를 노이즈로 셈.** 실루엣은 노이즈를 뺀 고유 시퀀스, TF-IDF 코사인.
  `hdbscan_uniq`는 고유 시퀀스 단위(복제 없음). 전체 표는 `ml/out/comparison.csv`.
- 고유 시퀀스 단위 HDBSCAN은 점이 26개뿐이라 군집을 하나도 못 만든다. 세션 단위로 바꾼 것이 필요했다.

**mcs=10, ms=10을 고른 이유**: 큰 군집 4개는 mcs=25/ms=25와 같고, `.ptmx` 드로퍼와 짧은 탐색 명령
(`shell ; sh`, `busybox SORA/LZRD`)을 별도 군집으로 분리하며, 노이즈가 33→11세션으로 줄어 공격 구분 목적에 더 맞다.
실루엣은 mcs=25가 더 높지만, 그 차이는 작은 그룹을 노이즈로 버려서 생긴 것이다. 아래 안정성 결과도 mcs=10 쪽이 낫다.

SSH(16세션, 고유 시퀀스 9개)는 어떤 설정으로도 군집이 2개 이상 나오지 않아 모델을 만들지 않았다.

## 4. 안정성

고유 시퀀스의 입력 순서를 무작위로 20번 바꿔 학습하고, fit과 같은 순서로 넣은 기준 결과와 비교했다.
ARI는 세션 단위로 계산했고 노이즈도 하나의 라벨로 셌다.
`ip_cap`은 같은 (src_ip, 시퀀스)를 최대 N개까지만 세는 실험 옵션이다(`--ip-cap`, 기본값은 꺼짐).

| 설정 | ip_cap | 군집 | 노이즈 | ARI 평균 | ARI 최소 | 기준과 같은 실행 | 바뀐 해시 그룹 |
|---|---|---:|---:|---:|---:|---:|---|
| **mcs=10, ms=10** | 없음 | 6 | 11 | 1.0000 | 1.0000 | 20/20 | 없음 |
| mcs=10, ms=10 | 5 | 5 | 23 | 1.0000 | 1.0000 | 20/20 | 없음 |
| mcs=25, ms=25 | 없음 | 4 | 33 | 0.9954 | 0.9838 | 7/20 | `.ptmx`(12세션) 5회, 1세션짜리 1개 8회 |
| mcs=25, ms=25 | 5 | 4 | 32 | 0.9951 | 0.9825 | 5/20 | `.ptmx` 5회, 1세션짜리 1개 13회 |

- 최종 설정은 입력 순서에 흔들리지 않는다. mcs=25의 불안정은 경계에 있던 `.ptmx` 그룹 때문이었다.
- `ip_cap=5`는 안정성에는 영향이 없고, 한 IP에서만 온 `.ptmx` 그룹(12세션)을 노이즈로 보낸다.
  "IP 하나의 반복은 군집으로 인정하지 않는다"는 정책을 원할 때만 켠다.

## 5. 군집 요약 (Telnet, mcs=10/ms=10)

공격 단위 = 같은 IP에서 이전 세션의 마지막 명령과 다음 세션 시작 사이가 10초 이내인 세션 묶음.
Telnet 1,401세션은 공격 단위 784개가 된다. 같은 IP의 연속 세션 간격은 10초 이내(617회)와
10분 초과(578회)로 뚜렷하게 나뉘고, 그 사이는 8회뿐이라 10초 기준이 적절하다.

| 군집 | 세션 | IP | 공격 단위 | 기간 | 대표 시퀀스(요약) |
|---|---:|---:|---:|---|---|
| 0 | 611 | 50 | 608 | 10-30 ~ 11-07 | `sh ; shell ; enable ; system ; ping ; sh ; /bin/busybox HISILICON ; /bin/busybox cat /proc/self/exe ; cat /proc/self/exe` |
| 1 | 609 | 50 | 607 | 10-30 ~ 11-07 | 위와 같이 시작 → `>/var/.f ; chmod <NUM> /var/.f ; /var/.f ; cd /var/` 를 `/var/tmp`, `/var/run`, `/dev`, `/dev/shm`, `/data` 등에서 반복 |
| 2 | 74 | 67 | 74 | 10-30 ~ 11-07 | `enable ; system ; shell ; sh ; linuxshell ; ping ; sh ; /bin/busybox hostname PBOC ; /bin/busybox echo > /tmp/.b ; sh /tmp/.b …` → `.k` 스크립트(깨짐) |
| 3 | 74 | 69 | 74 | 10-30 ~ 11-07 | 2번과 같은 앞부분 → `.k` 스크립트(정상) → Cowrie가 실행한 스크립트 줄 |
| 4 | 12 | 1 | 10 | 10-31 ~ 11-01 | `enable ; system ; shell ; sh ; >/tmp/.ptmx ; cd /tmp/ ; >/var/.ptmx ; cd /var/ …` (디렉터리 13곳) `… /bin/busybox HolyFuck` |
| 5 | 10 | 2 | 8 | 11-01 ~ 11-03 | `shell ; sh` (+ `/bin/busybox SORA` 또는 `LZRD`) |
| 노이즈 | 11 | 10 | 11 | 10-31 ~ 11-06 | 아래 해석 참고 |

해석(로그에서 확인한 사실과 추정을 구분했다):

- **0→1은 같은 봇의 한 공격이다.** 두 군집의 IP 50개 중 49개가 겹치고, 공격 단위 784개 중 604개가 `0→1` 조합이다.
  0번 세션이 끝나고 약 2.2초(중앙값, 최대 3.1초) 뒤 같은 IP가 1번 세션을 연다.
  0번은 `cat /proc/self/exe`로 자기 실행 파일을 읽고(아키텍처 확인으로 추정), 1번은 여러 디렉터리에 빈 파일 `.f`를 만들어
  실행 권한을 주고 실행해 본다(쓰기·실행 가능한 위치 탐색으로 추정). `busybox HISILICON`처럼 없는 애플릿을 부르는 것은
  Mirai 계열이 busybox 존재를 확인하는 방식과 같다(추정).
- **2·3은 같은 도구(PBOC)의 고장 버전과 정상 버전이다.** 앞 47개 명령이 같고, `echo -ne "\x.."`로 `.k`에 쓰는 스크립트만 다르다.
  - 3번은 `/proc/*/exe`가 `(deleted)`인 프로세스를 `kill -9`하는 정상 스크립트를 만든다(실행 파일을 지우고 숨은 경쟁 악성코드 제거).
    `sh .k`를 10번 실행하고, Cowrie가 그 스크립트 10줄을 매번 명령으로 기록해 시퀀스가 161개 명령으로 길다. 시그니처 B12가 100% 걸리고 군집 2에는 걸리지 않는다.
  - 2번은 같은 스크립트가 깨져서 써진다. 줄 이음 `\`와 `>> .k`가 따옴표 안으로 들어가고 끝에 `ar` 같은 쓰레기 문자열이 붙는다.
    문법 오류라 실행된 줄이 기록되지 않는다(60개 명령). 스크립트 생성이 고장 난 버전으로 보인다(추정).
- **4는 `.ptmx` 드로퍼다.** IP 하나(`45.90.163.37`)에서만 왔다. 디렉터리 13곳에 `.ptmx`를 만들고 들어가 본 뒤
  `/bin/busybox HolyFuck`으로 끝난다. 이 IP는 다른 세션들이 `curl.sh`, `wget.sh`, `jkl*` 바이너리를 내려받은 서버 주소이기도 하다
  (공격 서버가 직접 스캔도 하는 것으로 보임).
- **5는 짧은 탐색이다.** `shell ; sh` 후 `busybox SORA`/`LZRD`(Mirai 변종 이름)만 확인하고 끝난다. IP 2개(`103.123.134.4` 6세션, `45.198.224.106` 4세션).
- **노이즈(11세션)**: `./dvrHelper selfrep`까지 가는 728개 명령짜리 PBOC 변형(2세션, 둘 다 `45.90.163.37`에서 파일 6개씩 실제로 내려받음),
  다른 변종 이름(`KYTON`, `OWARI`, `FICORA`), 그리고 셸이 아닌 입력(HTTP `censys-agent`, SIP `OPTIONS`).

## 6. 시그니처 규칙 분포 (참고)

군집화 입력에는 쓰지 않았다. 각 군집의 세션 중 규칙에 걸린 세션 수다.
규칙은 팀원의 시그니처 작업(origin/main `fe94a96`, B14~B20·S02 추가, B01·B03·B04·B10·B11에 detector 추가)을
merge한 뒤 `match_signatures.py`를 다시 돌린 결과다.

| 군집 | 세션 | 걸린 규칙 |
|---|---:|---|
| 0 | 611 | B19 셸 진입 611, B01 시스템 사양 조사 610 |
| 1 | 609 | B11 실행 권한 609, B19 609, B08·B10·S01 각 1 |
| 2 | 74 | B10 스크립트 실행 74, B19 74, **B14 16진수 파일 기록 65**, B07 로그 지우기 6, B15 방화벽 비우기 2 |
| 3 | 74 | B10 74, **B12 경쟁 프로세스 죽이기 74**, **B14 74**, B19 74, B08·S01 각 1 |
| 4 | 12 | B01 12, B11 12, B19 12 |
| 5 | 10 | B19 10 |
| 노이즈 | 11 | B19 6, B10·B12·B14 각 3, B08·B11·S01 각 2 |

- **B19(Unix 셸 진입 요청)는 Telnet 대상 1,401세션 중 1,396세션(99.6%)에 걸린다.** `shell`/`sh`/`enable` 같은
  진입 명령은 거의 모든 Telnet 봇이 보내므로 군집을 구분하는 데는 도움이 안 된다. B19가 없는 5세션은 모두 노이즈(HTTP·SIP 스캐너 등)다.
- **B01이 detector로 `cat /proc/self/exe`를 잡게 되어** 이전에는 아무 규칙에도 걸리지 않던 군집 0이 B01(610/611)로 설명된다.
  군집 5는 여전히 B19 말고는 걸리는 규칙이 없다.
- **PBOC 군집 2·3에서 B14가 88%(65/74)와 100%로 갈려, ML의 구분과 일부 맞는다.** 군집 3은 B14가 100%이고,
  군집 2에서 B14가 걸린 65세션은 정확히 60개 명령짜리 시퀀스 그룹이다. 같은 군집 2에 묶인 82개 명령짜리 변형(6세션)과
  1세션짜리 3개에는 B14가 걸리지 않는다. 두 군집을 가장 깔끔하게 가르는 규칙은 B12(군집 3만 100%, 군집 2는 0)로,
  `.k` 스크립트가 정상인지(경쟁 프로세스 제거가 실제로 기록되는지)와 일치한다.
- 캠페인 규칙(C01~C05)은 여전히 어떤 세션에도 걸리지 않는다. S01(다운로드 → 실행 권한 → 실행)은 4세션(군집 1·3 각 1, 노이즈 2)에 걸린다.
- 규칙이 군집 0·4·5를 B01·B11·B19 조합으로만 설명하므로, `.ptmx` 드로퍼(4)나 짧은 변종 확인(5)처럼
  행동이 다른 묶음을 나누는 데는 군집 결과가 시그니처를 보완한다.

- **SSH 데이터 부족**: 명령어가 있는 SSH 세션이 16개(고유 시퀀스 9개)뿐이라 SSH 모델이 없다. SSH 세션은 군집·후보 결과에 들어가지 않는다.
- **IP 하나의 쏠림**: `221.161.112.140` 한 IP가 972세션(Telnet 대상의 69%, 군집 0·1의 80%)이다. 군집 크기는 공격 종류의 규모가 아니라
  이 IP의 반복 횟수를 크게 반영한다. 공격 단위로 묶거나 `--ip-cap`으로 보정할 수 있지만 아직 기본값에는 반영하지 않았다.
- **다운로드 전 중단**: 실제 파일을 내려받은 세션은 Telnet 4개(19개 파일, 모두 `45.90.163.37`)뿐이다.
  큰 군집들은 아키텍처 확인(`cat /proc/self/exe`)이나 빈 파일 실행 단계에서 끝난다. Cowrie가 진짜 장비처럼 바이너리 내용이나
  `shell`·`enable`·`system` 같은 장비 CLI 응답을 돌려주지 않기 때문으로 보인다(이 세 명령은 각각 1,386~1,399회 실패로 기록됨).
  그래서 군집은 "최종 악성 행위"가 아니라 "침투 초기 단계의 스크립트 모양"으로 나뉜다.
- **셸이 아닌 입력**: HTTP·SIP 스캐너 요청이 Telnet 명령으로 기록된다. 지금은 노이즈로 빠지지만 걸러 내는 규칙은 없다.
- **Cowrie가 기록한 스크립트 줄**: `sh 파일`을 실행하면 Cowrie가 파일 내용을 명령으로 기록해, 같은 도구라도 스크립트가
  정상인지에 따라 시퀀스 길이가 크게 달라진다(군집 2·3).
- **정규화 한계**: 셸 파서가 아니므로 따옴표 안의 `;`도 나눈다. `overlay2`, `/home/user2024a`처럼 무작위가 아닌 영숫자 혼합 이름도
  `<FILE>`이 되고, 16진수 이스케이프 문자열(`x69x6E…`)이 `<B64>`로, 숫자만 있는 디렉터리 이름이 `<HEX>`로 바뀌는 경우가 있다.
- **이상 점수**: 같은 시퀀스 반복 때문에 HDBSCAN의 GLOSH가 0/NaN이 되어, 가장 가까운 군집 중심까지의 거리로 대신했다.
  군집 안에서 얼마나 전형적인지는 반영하지만, 밀도 기반 이상 점수는 아니다.
- **기간·센서**: 시드니 한 곳, 약 열흘치다. 서울 데이터를 합치면 fit과 최종 파라미터 선택을 다시 확인해야 한다.
