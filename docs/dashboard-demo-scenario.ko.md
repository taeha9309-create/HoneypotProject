## 1. Overview — "지금 상황은?" (1분)

**화면**: 맨 위 빨간 배너

> 🔴 **위험** · 최근 7일(11-11~11-17) 상황: 새 다운로드 서버 1개 · 내려받아 실행 17세션 · 새 파일 해시 2개
> 접속 11,842세션(직전 7일 대비 **+40%**) · 위험도 높음 278세션

**말할 것**
- "대시보드를 열면 가장 먼저 **상황 등급**이 보입니다. 위험·주의·안정을 규칙으로 자동 판정하고, 왜 그런지 이유를 같이 적습니다."
- "이번 주는 **위험**입니다. 공격자가 실제로 파일을 내려받아 실행까지 간 세션이 17개 있었고, 처음 보는 파일도 들어왔습니다."

**화면**: 왼쪽 "지금 할 일" 카드

1. 1순위 IP **70개** 방화벽 차단 (2순위 181개는 검토)
2. 다운로드 서버 **8개**로 나가는 연결 차단·확인
3. 파일 해시 **29개** 백신·EDR 등록
4. 외부에 열린 Telnet·IoT 장비 점검 (접속의 **80%가 Telnet**)
5. 비밀번호 금지 목록 반영

**말할 것**
- "관리자는 통계보다 **할 일**이 필요합니다. 허니팟에서 본 것을 그대로 우리 회사 조치로 바꿔서 보여 줍니다."

**짧게 짚을 것** (스크롤하며 5초씩)
- 규모 카드: 접속 32,119 · 공격 IP 2,853 · 인증 시도 27,184(성공률 9.6%) · 우선 확인 278
- IP 집중도: "**상위 3개 IP가 세션의 절반 이상**입니다. 그래서 지도는 기본을 'IP 수'로 둬서 소수 IP의 반복에 속지 않게 했습니다."

(시간 여유가 있으면) "공격 계정" 탭 → **비밀번호 금지 목록 TXT** 버튼만 보여 주기

## 3. 세션 조사 — "이 공격은 정확히 무엇을 했나?" (1분)

**화면**: "한눈에 보기" 카드

> TELNET로 접속해 83초 동안 머물렀습니다. `admin / admin`로 로그인에 성공했습니다. 명령 32줄을 입력했고,
> 명령창 열기 → 정보 수집 → 실행 → 파일 들여오기 순서로 움직였습니다. 파일 관련 기록 6건(성공 1건)이 있습니다.
>
> ⚠ 우선 확인할 행동: 다운로드 후 실행

**말할 것**
- "보안을 잘 모르는 사람도 읽을 수 있게 세션을 **문장으로 요약**합니다. 공격 단계 칩에서 이 세션이 어디까지 갔는지 색으로 보입니다."
- "대만 IP가 기본 계정 `admin/admin`으로 들어와서, `185.93.89.72`에서 wget·tftp·ftpget을 차례로 시도하고, 결국 파일 하나를 받아 갔습니다."

**화면**: "무슨 일이 있었나 (시간순)" → 스크롤

- "같은 단계의 명령은 **한 줄로 묶어서** 32줄이 몇 줄로 줄어듭니다. 빨간 배지는 실제 탐지 규칙에 걸린 것, 노란 배지는 명령 모양으로 짐작한 설명입니다."
- 회색 상자의 원문: "URL은 `hxxp://`로 바꿔서 실수로 눌러도 열리지 않게 했고, 공격자 입력은 화면에서 실행되지 않게 처리했습니다."

**화면**: 오른쪽 "연결 근거 (S01)" — 다운로드 → 권한 → 실행 순서가 #번호로 표시됨

## 예상 질문과 답

| 질문 | 답 |
|---|---|
| 위험·주의·안정은 어떻게 정하나요? | 위험 = 새 다운로드 서버·내려받아 실행·새 파일 해시 중 하나라도. 주의 = 위험도 높음 행동이나 새 위험 IP. 그 외 안정. 전체 기간이면 최근 7일을 그 이전과 비교합니다. |
| 차단 후보 1순위 기준은? | 내려받아 실행, 다운로드 시도, 흔적 삭제·방화벽 해제·열쇠/예약 작업 심기 중 하나라도 한 공인 IP입니다. |
| 국가 정보는 정확한가요? | IP 기반 추정(DB-IP Country Lite, 오프라인)입니다. 공격자의 실제 위치가 아니며, 외부로 IP를 보내지 않습니다. |
| 머신러닝은 무엇을 썼나요? | 명령 시퀀스를 정규화(숫자·IP·URL·임의 파일명 치환)한 뒤 TF-IDF → SVD → HDBSCAN으로 군집화했습니다(팀의 `ml/cluster.py`). 서울+시드니 합본, Telnet 18개·SSH 2개 군집. |
| 왜 대부분 공격이 초반에 멈추나요? | Cowrie가 실제 IoT 장비처럼 응답하지 않아 봇이 장비 확인 단계에서 포기하는 것으로 봅니다. |
| 데이터는 어떻게 갱신하나요? | 새 로그를 받아 `build_db.py --ml` 한 번 실행하면 탐지·국가·군집까지 다시 만들어집니다. 원본 로그는 읽기만 합니다. |
| 공격자 입력을 화면에 보여 줘도 안전한가요? | 화면에 넣기 전에 모두 escape하고, URL은 `hxxp://`로 바꿔 링크가 되지 않게 했습니다. 목록의 IP는 가리고, 차단 목록용 IOC 화면만 전체를 보여 줍니다. |
