# 시그니처 후보 제안과 로컬 검사

## 대시보드에서 보기

갱신본을 연 다음 **후보 검토 → 자동으로 찾은 검토 대상**에서 군집을 선택하고 **후보 제안 및 로컬 검사**를 누른다. 보관 로그를 사용한 1차 판단이며 외부 AI를 호출하지 않는다. 규칙 파일과 승인 기록은 그대로 둔다.

1. 규칙에 일치하지 않거나 B19만 일치한 세션에서 반복 흐름이 있는 군집을 찾는다.
2. 로컬 예시 제공자가 가린 대표 흐름을 바탕으로 명령 순서 초안을 제안하거나 판단을 보류한다.
3. 초안이 있으면 같은 프로토콜의 전체 로컬 세션에 적용해 전체·원래 군집·군집 밖의 일치 건수를 나눠 표시한다. 모델이 배정하지 않은 세션과 노이즈도 군집 밖 검사에 포함한다.
4. 기존 규칙과 겹치는 건수, B19 단독 적중 세분화, 이전에 규칙이 없었던 일치, IP 개수와 최대 IP 비중을 확인한다. 같은 초안이 다른 군집에서 나왔으면 군집 번호를 함께 표시한다. 선택한 검토 결과는 JSON으로 내려받을 수 있다.

## 갱신에 포함되는 결과

새 갱신본에는 `signature_review_groups.json`과 `signature_proposal_validation.json`이 함께 생성된다. 기존 갱신본에 두 번째 파일이 없으면 아래처럼 별도 실행할 수 있다. 규칙 파일을 지정해 만든 갱신본이라면 검사에도 같은 `--rules`를 사용한다.

```powershell
python -m ml.analysis.signature_validation --data-dir "work/operations/refresh-one-command-20261128"
```

보고서의 건수는 **가려진 명령 라벨의 연속 순서가 일치한 결과**다. 군집을 찾는 데 사용한 같은 갱신본에서 계산하므로 초안의 실제 탐지 정확도나 독립 검증을 뜻하지 않는다. 다른 규칙과의 중복이나 군집 밖 일치 자체로 오탐을 확정하지 않는다. 가려진 인수는 초안 조건으로 추측하지 않고, 명령 원문이나 IP 전체는 보고서에 싣지 않는다.

## 보관 자료 확인 사례

11월 25일까지의 보관 자료에서 검토 대상 군집 7개를 검사했다. 3개 군집에서 초안이 제안됐고, 그중 두 군집의 초안이 같아 서로 다른 초안은 2개였다. 나머지 4개 군집은 판단을 보류했다.

| 로컬 초안 | 텔넷 8,703세션 중 일치 | 다른 구체 규칙과 중복 |
|---|---:|---:|
| 장비 메뉴 탐색 입력 순서 | 543 | 0 |
| 셸 진입 뒤 환경 탐침 입력 | 472 | 0 |

메뉴 탐색 초안의 543건 중 258건은 처음 고른 군집 밖에서도 일치했다. 전체 일치 세션과 군집 밖 일치 세션을 분리해 보는 이유다.

실제 AI API가 준비되면 가려진 대표 흐름과 집계를 사용하는 제공자만 연결한다. 제안 응답의 근거와 단계 위치를 같은 방식으로 확인한 후 이 검사 경로를 사용한다. 운영 규칙 등록과 배포는 승인 절차를 별도로 거친다.
