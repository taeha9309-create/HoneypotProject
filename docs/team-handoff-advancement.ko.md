# [팀원 전달] 고도화 방향 요약과 요청 사항

작성: 2026-11-28. 상태: **Draft** (팀원 확인 전). 세부 명세는 `docs/advancement-spec.ko.md`, 분석 근거는 `docs/advancement-analysis.ko.md`, 이상 점수 문제는 `docs/handoff-cluster-outlier.ko.md`에 있다. 이 문서는 팀원이 읽기 쉽게 요약한 것이다. 아래 "역할 분담"은 제안이며 팀원과 합의해서 확정한다.

## 1. 전체 고도화 방향

MVP 이후 목표는 화면이나 기능을 늘리는 것이 아니라 **시그니처와 ML 군집화를 연결해 규칙이 구체적으로 식별하지 못한 행동을 찾고, 규칙 후보를 만들어 검증하는 폐루프**를 만드는 것이다.

```
규칙 간극 발견 → 규칙 후보 생성 → 근거·관련 세션 제공 → 관리자 승인/거부 → 승인 규칙 반영(버전 관리) → 반영 전후 비교
```

- 군집화가 **단순 그룹핑보다 실제로 이점이 있는지**를 같은 조건으로 비교한다(A 시그니처만 / B 고유 순서 그룹핑 / C 편집 거리 / D ML 군집). 이점이 없으면 없다고 보고한다.
- 연구 가능성(외부 학회 제출 여지)과 제품 가치(운영자가 쓸 수 있는 결과)를 같이 본다. 사용자 가치 주장은 인터뷰 전까지 가설이다.
- 자동 규칙 반영은 하지 않는다. 승인과 검증이 필수다.
- 대시보드 디자인 고도화는 추후에 한다. 지금은 기존 화면·기능을 유지한다.
- **기존 MVP 코드와 기준선(규칙 29개, 테스트)은 보존한다.** `ml/cluster.py`는 팀원 승인 없이 수정하지 않는다.

현재 완료한 것: 분석·용어집·ADR 초안·명세, T0(기존 ML 코드 수정 없이 훈련 구간만 학습 + 이후 구간 배정 가능 확인), T1(기준선, 분할 3종, 결정성 검증). 결과는 `docs/advancement-analysis.ko.md` 10절.

## 2. ML 담당자에게 요청할 사항

1. **이상 점수 문제 검토와 수정 여부 결정** (아래 3절, `docs/handoff-cluster-outlier.ko.md`). 수정은 팀원이 승인하고 방식을 정한 뒤에만 한다. 우리는 화면에서만 하한 0.05로 보정해 두었다.
2. **훈련 전용 모델 평가 방식 확인**: 평가를 공정하게 하려고 `cluster.py`의 `fit`/`assign`을 **수정 없이 import해서** 사본 DB에서 훈련 구간만으로 학습하고 이후 구간을 배정한다(`ml/analysis/splits.py`). 이 사용 방식이 의도한 사용법과 맞는지, 놓친 부작용이 있는지 봐 달라.
3. **파라미터 타당성**: 고정 파라미터(`mcs=10, ms=10`)는 2026-11-07 시드니 텔넷 데이터 기준이다. 서울+시드니 합본과 훈련 전용 분할(예: 시드니만 학습)에서 다시 검증이 필요한지 의견을 달라. 우리 분할에서 시드니만 학습하면 군집이 9개뿐이고(SSH 모델은 표본 부족으로 없음) 서울 세션의 25.6%가 노이즈로 배정된다.
4. **PR #4(자동화 파이프라인) 상태**: 현재 main과 충돌하는지, 계속 진행할 의사가 있는지 알려 달라. 우리는 머지하거나 수정하지 않았다.
5. **군집 번호 변경 통지**: 운영용 모델을 다시 학습하면 군집 번호가 바뀐다(서울+시드니 합본 재학습으로 이미 한 번 바뀌었다). 재학습 전에 알려 달라.

## 3. 이상 점수 문제 요약과 재현 근거

- **현상**: `novel_candidates.csv`의 outlier 판정이 점수가 사실상 0인 세션까지 포함해 후보가 부풀려진다.
- **원인**: 프로토콜 전체 점수의 95분위수를 임계값으로 쓰는데, 같은 순서를 반복하는 봇 때문에 점수의 대부분이 0 근처에 몰려 95분위수가 0.00002가 된다. 점수는 정확히 0이 아니라 부동소수점 오차(1e-9~1e-6)라서 `sc > 0` 조건이 걸러 내지 못한다.
- **재현 근거(현재 데이터, 텔넷 8,703세션)**: 정확히 0은 10.2%, 1e-9 이하 50.6%, 1e-6 미만 91%, 95분위수 0.00002. outlier로 판정된 761세션 중 점수가 0.05 이상인 것은 122개뿐이다. `novel_candidates.csv` 원본은 106종·785세션, 화면 보정 후 87종·146세션.
- **훈련 전용 모델에서도 같은 분포**: 시간 분할 훈련 전용 모델에서도 1e-6 미만이 80%였다(`work/advancement/T0_20261128.md`). 즉 데이터 구간 문제가 아니라 판정 방식 문제다.
- **재현 방법**: `docs/handoff-cluster-outlier.ko.md`의 읽기 전용 파이썬 코드.
- **권장**: 절대 하한 병행(예: 0.05), 최소한 `sc > 0`을 허용 오차(예: 1e-6)로 변경, 고유 순서 단위 계산, 군집별 기준. 하한 값은 점수 분포를 같이 보고 정하자.

## 3-1. 검토를 요청하는 두 가지 문제 (T1·T2에서 발견)

**(1) 단일 IP 편중**
- 시드니 데이터의 **IP 하나가 전체 명령 세션의 60.1%** 를 차지하고, 상위 2개 명령 순서가 89.9%다(고유 순서 62개). 시드니만으로 학습하면 한 캠페인이 모델을 지배한다.
- 서울도 완화되지만 같은 성격이다(상위 IP 23.8%, 상위 2개 순서 55.8%).
- 우리가 한 실험(개발 단계, 탐색적): 훈련에서 최상위 IP 세션 2,722개(60%)를 빼도 **고유 순서 단위 결과는 그대로**였다(그 IP의 순서가 다른 IP에서도 나오기 때문). 반면 `fit`의 기존 `ip_cap=1`(같은 IP+같은 순서를 1세션으로 셈)을 쓰면 군집이 9개에서 5개로 줄고 서울 평가 세션의 노이즈가 25.6%에서 32.5%로 늘었다. 즉 **IP 편중 처리 방식이 군집 구조에 영향을 준다.**
- 요청: 운영 모델에서 `ip_cap`을 어떻게 쓰는 게 좋은지, `mcs=10`이 IP 편중 상황에서 타당한지 검토해 달라.

**(2) 훈련에 없던 순서의 높은 노이즈 배정 비율**
- 시드니만 학습한 모델이 서울의 **훈련에 없던 순서 1,393세션 중 1,052세션(75.5%)을 노이즈로 배정**한다(`approximate_predict`).
- 노이즈로 간 순서를 따로 분석해 보니(T2): 노이즈 순서 30개 중 14개는 **기존 규칙이 구체적으로 식별하는 행동**이고 5개는 B19만 걸리고 11개는 규칙이 없다. 즉 "정말 새로운 것"이 아니라 **훈련 허니팟에 없던 행동 계열**이 상당수다. 노이즈를 새 공격으로 해석할 수 없다.
- 우리는 노이즈를 제외하거나 한 군집으로 합치지 않고 별도 분석 대상으로 두고 있다. 처리 방식에 따라 비교 결과가 크게 달라진다(제외하면 정확 일치 그룹핑이 100%로 보이는 식의 왜곡이 생긴다).
- 요청: 미관측 순서를 노이즈가 아니라 가까운 군집에 배정할 방법(예: 소속 확률 임계값, 최근접 군집 배정 후 점수 표시)이 의미가 있는지 의견을 달라.

**실험 결과 공개(T2, 개발 단계 탐색적)**: 시드니→서울에서 훈련에 없던 순서 중 규칙 서명이 있는 36개의 규칙 일치 배정은 정확 일치 0개, 편집 거리 11개(30.6%), **ML 군집 9개(25.0%)** 였다. 시간 분할과 서울→시드니에서는 편집 거리와 ML 군집이 같았다(9/12, 7/12). 즉 **현재 데이터에서 ML 군집이 편집 거리 기반 묶음보다 낫다는 증거는 없다.** 표본이 매우 작고 신뢰구간이 없다. 이 결과는 ML 코드를 개선하면 달라질 수 있으니 개선판이 나오면 같은 실험을 다시 한다.

**모델 버전 관리**: 우리 실험은 현재 `ml/cluster.py`(sha256 `a949b204…`, 정규화 버전 3, `mcs=10 ms=10 max_copies=50 ip_cap=0`)로 했고 결과 파일에 `ml_version`으로 기록한다. 팀원이 개선한 버전이 나오면 별도 버전 이름으로 같은 실험을 다시 하고 두 결과를 섞지 않는다. 개선판이 확정되면 알려 달라(동결 시점 F 이전이어야 한다).

## 5. 공동 실험과 라벨링 계획

- **실험**: A·B·C·D 비교(고유 순서 그룹핑 필수, 편집 거리 가능하면). 평가는 E1(기존 규칙 복원 실험, 실제 미지 공격 탐지 성능이 아니다), E2(사람 판정), E3(신규 행동 규칙 X04·X06 유효성). 분할은 시간 분할, 시드니→서울, 서울→시드니 세 가지다.
- **사람 판정**: 100개. 사용자와 팀원이 각자 60개(단독 40 + 공통 20), 공통 20개로 Cohen's κ를 낸다. 범주(초안, 판정 전에 동결): ① 셸 진입만 ② 장비·환경 정찰 ③ 도구/파일 반입 시도 ④ 지속성·정리 시도 ⑤ 기타·판정 불가. 입력 문자열에서 보이는 행동만 매기고 성공·악성 여부는 매기지 않는다.
- **판정 원칙**: 시트에는 규칙·군집·후보 정보를 넣지 않는다(앵커링 방지). 두 사람이 서로의 판정을 보지 않고 각자 한다. 기준을 바꾸려면 새 버전으로 기록하고 다시 판정한다.
- **일정**: 시트는 T6에서 만든다. **판정 시기를 팀원이 정해 달라.** 정해지기 전에는 E2를 보류한다.

## 6. 시드니 데이터 지속 수집과 보존 요청

최종 평가는 **동결 시점 F 이후에 수집된 새 데이터**로만 한다(기존 11/18~25 구간은 이미 규칙 검증에 쓰여서 독립 평가라고 주장할 수 없다). 그래서 다음이 필요하다.

1. **시드니 허니팟을 계속 켜 두고 수집을 유지**한다. 중단·초기화·재설치를 하지 말아 달라.
2. **원본 Cowrie 로그(`cowrie.json`, 날짜별 회전 파일)를 보존**한다. 지금은 DB 사본만 받아서 인증 실패·파일·서버 정보가 비어 있다. 가능하면 원본 로그를 전달해 달라.
3. 로그를 **삭제하지 않고 보존**한다(로테이션·디스크 정리 설정 확인). 전달 시 파일 해시(sha256)를 같이 알려 주면 좋다.
4. **11/25 이후 데이터는 우리가 동결(F)하기 전에는 열어 보지 않는다.** 팀원도 분석 결과를 우리에게 미리 공유하지 말아 달라(평가 독립성 때문). 전달은 가능하되 F 이후에 같이 열자.
5. 전달 방식: IP·공격 입력이 들어 있으므로 저장소(git)에 올리지 않고 개인 전달로 한다.
6. 서울 로그는 우리가 가져온다. 서울도 11/25 이후 로그는 F 전에 열지 않는다.
