# 허니팟 공격 분석 대시보드 기획서 v2 (Streamlit)

작성일: 2026-11-17 · 상태: **초안 (검토 중)** · 이전 문서: `docs/dashboard-plan-v1.ko.md`(handoff 브랜치), 기획서 v2.0 초안

> v1에서 원칙·데이터 기준·지표 정의는 가져오고, 구현 기록(커밋·포트·검증 수치)은 작업 로그로 뺐다.
> 지도 연출과 전용 화면은 MVP 이후로 미룬다.

## 1. 목적과 관리자 질문

허니팟에 수집된 SSH/Telnet 접속을 **"얼마나 들어왔나 → 무엇을 확인할까 → 근거는 무엇인가"** 순서로 보여 주는 관리자용 대시보드.

화면은 아래 질문에 답해야 한다. 질문에 답하지 않는 카드는 넣지 않는다.

| # | 관리자 질문 | 답하는 곳 |
|---|---|---|
| Q1 | 이 기간에 얼마나 들어왔고, 평소보다 많은가? | Overview 핵심 통계·추이 |
| Q2 | 실제로 위험한 단계까지 간 세션이 있는가? | Overview 우선 확인 세션 → 세션 상세 |
| Q3 | 공격자들은 주로 무엇을 하려 했는가? | Overview 주요 행동 TOP 5 |
| Q4 | 어떤 파일이 들어오려 했는가? | Overview 수집 파일 → 세션 상세 |
| Q5 | 어떤 계정으로 들어오려 했고, 얼마나 성공했는가? | Overview 인증 요약 |
| Q6 | 어디서, 누가(어느 IP가) 반복해서 오는가? | Overview 지도·반복 IP → IP 상세 |
| Q7 | 이 IP / 이 세션은 정확히 무엇을 했는가? | 세션·IP 상세 |
| Q8 | 허니팟 데이터는 언제까지 반영됐고 빠진 구간은 없는가? | 데이터 상태 표시 |

## 2. 범위

| 구분 | 포함 |
|---|---|
| **MVP** | ① Overview ② 세션·IP 상세(조사 화면) ③ 서울·시드니 통합 조회 ④ 공통 필터(기간·출처·프로토콜) |
| 후속 | 탐지 규칙 화면, ML 군집 화면(통합 재학습 여부 결정 후), 파일·인증 전용 화면, 지도 궤적 연출, 내보내기 |
| 제외 | 자동 수집·정기 분석·알림, 공개 배포·관리자 인증 |

기술: Python + Streamlit + SQLite(읽기 전용). 기존 `ingest.py`, `match_signatures.py`, 규칙, ML 코드는 수정하지 않고 가져다 쓴다.

## 3. 데이터와 통합 원칙 (v1 8절 유지)

1. 본인·팀원 원본 로그와 DB를 각각 보존한다. 대시보드는 **별도 대시보드용 DB**만 읽는다.
2. 수집 위치·센서·기간·시간대·분석 버전을 확인하고 화면에 표시한다.
3. 같은 자료의 중복 사본과 실제 반복 접속을 구분한다.
4. 모든 연결 키는 `(source, session_id)`. 출처: `seoul`, `syd`.
5. 저장된 분석 결과와 새 재평가 결과를 구분한다(탐지 규칙 버전 표시).
6. 서로 다른 ML 실행의 같은 군집 번호를 같은 군집으로 합치지 않는다.
7. 전체 기간과 두 허니팟의 공통 기간을 나눠 비교할 수 있게 한다.
8. 통합 전후 행 수·제외 수·중복 수를 검증하고 기록한다.

### 3.1 MVP 데이터 구성

| 자료 | 내용 | 비고 |
|---|---|---|
| `sessions/commands/downloads/failed_commands` | 기존 ingest 결과 | 출처별 DB |
| `signature_hits` | 현재 `rules.yaml`로 재계산 | 규칙 커밋 표시 |
| `login_events` | 원본 로그의 인증 성공·실패 이벤트 | handoff의 `import_auth.py` 방식 재사용 (세션·시간·IP 일치 검증) |
| `download_events` | 다운로드 성공·실패, 업로드 | **신규 수집 필요**. 실패는 해시 없이 별도 집계 |
| GeoIP | IP → 국가 (오프라인) | 공급원 결정 필요(5절) |

## 4. 지표 정의 (v1 9절 유지 + 보완)

| 항목 | 기준 |
|---|---|
| 표시 시간 | KST. 원본 UTC 보존 |
| 기간 경계 | 시작일 00:00 포함, 종료일 다음 날 00:00 미만 (KST) |
| 접속 세션 | 시작 시각 기준 고유 세션. `excluded=1`(테스트 접속) 제외 |
| 명령·인증·다운로드 | 각각 발생 시각 기준 |
| 인증 성공률 | 성공 인증 이벤트 / 전체 인증 이벤트 |
| 우선 확인 세션 | 아래 규칙 중 하나라도 일치한 **고유 세션**. 규칙별 수 단순 합산 금지 |
| 변화율 | 직전 동일 길이 기간 대비. 전체 기간 조회나 비교 자료 부족 시 생략 |
| 신규 (확정) | 전체 기간: "누적 고유 항목"으로 표시. 기간 선택 시: **조회 시작 이전 보유 데이터에 없던 항목** |
| 데이터 없음 | 0건 / 미수집 / 조회 실패를 구분 표시 |
| 센서 상태 | 마지막 이벤트 시각과 마지막 가져오기 시각을 구분. 무접속만으로 장애 판정 금지 |

**우선 확인 규칙(초안):** S01 다운로드→권한→실행, S02 디코딩→인터프리터, B04 SSH 키 쓰기, B05 crontab 등록, B07 로그 삭제, B06 기록 끄기, B15 방화벽 비우기.

## 5. 표시·보안 원칙

- 공격자 입력은 실행하지 않고, HTML로 해석하지 않는다(`unsafe_allow_html` 금지).
- URL은 `hxxp://`로 바꾸고 링크로 만들지 않는다. 외부 URL·해시 조회를 자동으로 하지 않는다.
- 공격자 IP 표시 방식: **결정 필요** (관리자 화면이므로 전체 표시 vs `a.b.x.x` 가림 + 상세에서만 전체).
- 탐지는 "입력 관측"이며 실행 성공·악성 확정이 아니다. 화면에 짧게 고지한다.
- **행동 설명(쉬운 이름)과 시그니처 탐지를 분리한다.** 설명이 붙어도 탐지 건수는 바뀌지 않고, 근거 종류(규칙 일치 / 입력 기반 추정 / 근거 부족)를 함께 표시한다.
- 지도: 출발지는 국가 단위 추정, 위치 미상은 별도 수치, 가상 출발지 금지, 수동 사본을 실시간처럼 보이지 않기.

## 6. 화면 설계

### 6.1 공통

- 사이드바: 기간(전체 / 하루 / 시작·종료), 출처(서울·시드니), 프로토콜. **모든 카드와 목록에 같은 범위 적용.**
- 상단에 조회 범위 문구: "전체 기간 10-27 ~ 11-17 (KST)" 또는 "선택 기간 …".
- 목록의 IP·세션을 누르면 세션·IP 상세로 이동하며 필터를 유지한다.

### 6.2 Overview (위에서 아래 순서)

| 구역 | 내용 | 질문 | 완료 기준 |
|---|---|---|---|
| 데이터 상태 줄 | 출처별 마지막 이벤트·가져오기 시각, 수집 공백 경고 | Q8 | 출처마다 시각 2개 표시, 1시간 이상 공백 구간 수 표시 |
| 핵심 숫자 5개 | 접속 세션, 고유 IP, 인증 시도(성공률), 명령 입력, 우선 확인 세션 | Q1·Q2 | 직전 기간 대비 변화율, 0건/미수집 구분 |
| 접속 추이 | SSH/Telnet별(또는 출처별) 시계열. 하루 선택 시 시간 단위 | Q1 | 전체 기간=일, 하루=시간 |
| 지도 | 국가별 분포(2D). 하루 선택 시 시간순 재생 | Q6 | 위치 미상 수 별도 표시 |
| 우선 확인 세션 | **행동별 세션 수** 막대 + 최근 5건 → 상세 | Q2 | 고유 세션 수와 규칙별 수가 분리됨 |
| 주요 행동 TOP 5 | 쉬운 행동명 가로 막대 (명령 세션 대비 %) | Q3 | 근거 종류 표시 |
| 인증 요약 | 성공·실패 비율, 시도 계정·비밀번호 TOP | Q5 | 실패 시도 포함 |
| 수집 파일 | 파일명·관련 세션 수·최근 관측, 해시 축약+복사 | Q4 | 실패 건수 별도 |
| 반복 접속 IP | IP별 세션 수·활동일·대표 행동 TOP | Q6 | 클릭 시 IP 상세 |
| 최근 입력 명령 | 시각·IP·명령(축약)·행동 설명·탐지 여부 20건 | Q3·Q7 | 클릭 시 세션 상세 |
| 신규 항목 | 신규 IP·명령 패턴·파일 해시 수 | Q1 | 4절 신규 정의 적용 |

### 6.3 세션·IP 상세

- **IP 상세:** 국가, 첫·마지막 접속, 활동일, 세션 수, 사용 계정, 탐지 행동, 다른 허니팟 방문 여부, 세션 목록.
- **세션 상세:** 메타정보, 인증 이력, 명령 타임라인(행동 설명 + 규칙), 실패 명령 조각, 다운로드 관측, S01/S02 연결 근거.
