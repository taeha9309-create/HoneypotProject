# 후보 저장과 검토 이력

새 대시보드 갱신이 끝나면 로컬 초안 검사 보고서를 공용 후보 저장소 `work/review/candidates.db`에 등록한다. 프로토콜과 가려진 명령 순서가 같으면 같은 후보 ID를 사용한다. 군집 번호와 설명 문구는 후보 ID에 포함하지 않는다.

각 갱신본의 규칙 해시·빌드 시각·모델 학습 시각으로 발견 이력을 구별한다. 같은 보고서를 반복 등록해도 같은 군집 근거가 중복되지 않는다. 다른 갱신본의 근거가 추가돼도 이미 승인·거부한 상태와 사유는 유지한다. 데이터베이스 트랜잭션으로 후보와 근거를 함께 기록한다.

기존 보고서를 등록하거나, 갱신 완료 후 후보 저장 단계만 다시 실행할 수 있다.

```powershell
python -m ml.analysis.proposal_registry --report "work/operations/refresh-local-proposals-20261128/signature_proposal_validation.json"
```

대시보드 **후보 검토 → 저장된 검토 후보**에서 후보를 선택하면 상태와 발견 이력, 전체·군집 밖 일치, B19 단독 적중 세분화 수를 볼 수 있다. 후보 ID와 이력 JSON도 내려받을 수 있다. 보류된 제안은 검토 후보로 등록하지 않는다.

검토 결정은 기존 명령을 사용한다. 검토자의 실제 이름과 사유를 기입한다.

```powershell
python -m ml.analysis.candidate_registry --registry work/review/candidates.db reject <후보ID> --reviewer "<검토자>" --reason "<검토 사유>"
```

승인할 때는 `reject` 대신 `approve`를 사용한다. 가려진 명령 라벨 초안을 운영 규칙으로 내보내려면 실제 탐지 엔진에 사용할 정규식과 적용 범위를 별도로 검증해야 한다. 현재 버전 내보내기는 이 형식의 초안을 차단한다.

검토용 저장소는 git 제외 폴더에 있다. 기존 X06 동결·검토 기록은 별도로 유지한다. 실제 AI API가 준비되기 전까지는 로컬 예시 제공자를 사용한다.

## 화면에서 검토 결과 기록

**후보 검토 → 저장된 검토 후보**에서 후보를 선택하고 근거를 확인한다. 검토 대기 상태이면 아래에 검토자, 판정 사유, 승인·거부 선택과 **검토 결과 저장** 버튼이 표시된다. 세 항목을 모두 입력한 후 저장하면 새로고침된 화면에 판정자·시각·사유가 표시된다. 판정이 끝난 후보는 같은 폼에서 다시 판정할 수 없다. 기존 CLI 판정과 같은 절차를 사용하며, 가려진 라벨 초안의 운영 규칙 내보내기 제한도 계속 적용한다.
