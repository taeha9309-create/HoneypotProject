# 대시보드 갱신본 만들기

서울 로그와 시드니 DB 사본을 준비한 뒤, 프로젝트 폴더에서 아래처럼 한 번 실행합니다. `--out`에는 새 폴더 이름을 지정합니다.

```powershell
python -m streamlit_app.refresh_dashboard --seoul-logs "D:\보관\서울로그" --syd-db "D:\보관\시드니.db" --geo "work\geo\dbip-country-ipv4.csv" --out "work\operations\refresh-새날짜"
```

명령은 탐지 결과와 ML 군집을 임시 위치에서 새로 만들고 검증합니다. 성공하면 지정한 새 폴더에 결과를 저장하고, **서버별 최신 관측 시각·세션 수·규칙 적중 수·ML 배정 수**를 표시합니다. 같은 내용은 해당 폴더의 `refresh_summary.json`에도 저장됩니다. 시각은 UTC이며 규칙 적중 수는 세션 수와 단위가 다릅니다.

화면에서 확인하려면 성공 메시지 아래에 출력된 PowerShell 명령을 복사해 실행합니다. 기존에 사용 중인 데이터 폴더를 계속 사용할 수 있고, 출력 폴더 이름에 이미 존재하는 폴더를 지정하면 실행이 중단됩니다. 오류가 나면 원인을 확인한 뒤 다시 실행합니다.

서울이나 시드니 한쪽만 있으면 해당 옵션만 지정할 수 있습니다. 이 경우 결과에는 지정한 출처만 포함됩니다. 국가 조회 파일이 없으면 `--geo`를 생략할 수 있습니다. 전체 재학습이 포함되므로 군집 번호는 이전 결과와 달라질 수 있습니다.

## 새 갱신본에서 시그니처 검토 대상 보기

갱신 명령은 새 폴더에 `signature_review_groups.json`을 만들고, 대시보드 **후보 검토 → 자동으로 찾은 검토 대상**에 표시한다. 기존 갱신본은 프로젝트 루트에서 `python -m ml.analysis.signature_review_groups --data-dir <갱신본 폴더>`로 한 번 분석할 수 있다.

초기 선별 조건은 미적중 또는 B19만 적중한 세션이 해당 군집에 3건 이상이고 절반 이상이며, 셸 진입만 하는 경우를 제외한 같은 정규화 흐름이 그중 2회 이상 반복되는 것이다. 노이즈는 별도 집계한다. 화면에는 입력 인수를 가린 대표 흐름과 집계만 표시한다. 이 단계는 검토 대상을 찾으며, 시그니처 제안 및 승인 기록은 이후 단계다.

### AI 제안 시험

**후보 검토 → 자동으로 찾은 검토 대상**에서 군집을 선택하고 **후보 제안 및 로컬 검사**를 누른다. 로컬 시험 제공자는 가려진 명령 흐름과 집계만 받아 행동 설명, 근거, 순서 초안 또는 보류 사유를 표시한다. 이 단계에서는 외부 API와 운영 규칙을 사용하지 않는다. 표시된 초안은 근거 흐름의 연속된 위치만 참조하며, 상세 인수가 가려져 있는 단계는 규칙 조건으로 제안하지 않는다.

[후보 제안과 로컬 검사 안내](signature-proposal-validation.ko.md)에서 군집 밖 일치, 기존 규칙 중복, B19 단독 적중 세분화의 확인 방법을 볼 수 있다. 새 갱신본에는 후보 검사를 포함한다.
