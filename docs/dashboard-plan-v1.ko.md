# 허니팟 공격 행동 분석 대시보드 기획서

작성일: 2026-11-11 · 버전: 1.0 · 상태: 재기획 초안

이 문서는 앞으로 만들 대시보드의 요구사항을 정의한다. 기존 화면은 기능 검증용 초안으로 취급하며, 현재 구현 방식이 최종 기획을 제한하지 않는다. 기존 수집·시그니처·ML 분석 코드는 가능한 한 재사용한다. 이번 재기획에서는 애플리케이션 코드나 운영 DB를 변경하지 않는다.

## 1. 서비스의 목적

**관리자가 허니팟에 하루 동안 어떤 접속이 들어왔는지 파악하고, 반복 접속 IP에서 개별 세션·명령어·탐지 근거·ML 군집까지 확인하는 분석 도구를 만든다.**

화면이 답해야 하는 핵심 질문은 다음과 같다.

1. 어제 얼마나 많은 이벤트·접속·인증 시도·명령어가 발생했는가?
2. 어느 출발 IP와 추정 국가에서 접속이 많이 들어왔는가?
3. 같은 IP가 얼마나 자주 다시 들어오고, 어떤 행동을 반복했는가?
4. 어떤 계정과 비밀번호가 시도되었으며 인증 결과는 무엇인가?
5. 어떤 명령어가 어떤 시그니처에 일치했는가?
6. 비슷한 명령어 패턴은 어떤 군집으로 묶였고, 미분류 패턴은 무엇인가?
7. 지금 보는 자료가 최신 수집 데이터인지, 과거 사본인지 알 수 있는가?

접속이나 시그니처 일치를 실제 침해 성공·악성 확정으로 표현하지 않는다.

## 2. 요구사항의 확정 수준

| 구분 | 내용 |
|---|---|
| 사용자 요청으로 포함 | Overview 우선 개편, 어두운 카드형 디자인, 로그인 시도·계정·비밀번호 통계, 공격 지도, 하루 빠른 재생, 실시간 확인 버튼, 반복 접속 IP, SSH/Telnet 원형 차트 |
| 앞서 요청한 핵심 기능 | Sessions 목록·필터·상세·명령어 흐름, 한국어 시그니처명·코드·근거, 실제 ML 결과의 군집 그림·상세 |
| 검토 중인 방향 | 기존 DB와 전달받은 시드니 DB를 함께 보기. 아직 통합 구현이나 서울 출처 확인을 완료한 상태는 아님 |
| 이 문서의 권장안 | 아래 화면 구성, 집계 정의, IP 상세 패널, 데이터 상태 표시, 구현 단계와 완료 기준 |
| 아직 결정하지 않음 | 최종 디자인 세부안, 원본 로그 전달·동기화 방식, 자동 일일 보고서·알림, 운영 배포·계정 관리 |

## 4. 사용자 흐름과 메뉴

### 4.1 주요 사용 흐름

**일일 확인:** Overview → 어제 선택 → 지도 재생·반복 IP 확인 → IP 상세 → 세션 상세 → 명령어·탐지 근거 확인.

**현재 확인:** Overview → 실시간 모드 → 새 접속·수집 지연 확인 → 관심 IP 또는 세션 선택.

**행동 분석:** Detection 또는 ML Analysis → 규칙/군집 선택 → 관련 세션 목록 → 명령어 원문 확인.

### 4.2 화면 구조

| 메뉴 | 목적 | 중심 정보 |
|---|---|---|
| Overview | 하루 현황과 변화 파악 | 통계, 지도, 재생, 반복 IP, 인증·프로토콜 분포 |
| Sessions | 접속별 행동 조사 | 필터 목록, 세션 상세, 인증·명령어 타임라인 |
| Detection | 규칙 일치 결과 검토 | 한국어 행동명, 코드, 탐지 근거, 관련 세션 |
| ML Analysis | 유사 행동 패턴 탐색 | 군집 그림, 군집별 규모·대표 패턴, 미분류 |
| IP 상세 패널 | 한 IP의 반복 행동 조사 | 접속 이력, 시간대, 계정·행동·탐지·군집 요약 |

IP 상세는 초기에는 별도 메뉴보다 Overview·Sessions에서 여는 패널이나 상세 페이지로 구성한다. 지도도 초기에는 Overview 안에 둔다. 데이터 상태는 모든 화면에서 접근 가능한 공통 영역으로 둔다.

## 5. 공통 조회·표시 규칙

| 항목 | 권장 기준 |
|---|---|
| 표시 시간 | KST. 원본 UTC는 유지하며 화면에 KST 기준을 명시 |
| 하루 범위 | 선택일 00:00 이상, 다음 날 00:00 미만 |
| 공통 필터 | 날짜/기간, 출처·센서, SSH/Telnet/미상 |
| 화면 이동 | Overview에서 선택한 날짜·출처·IP가 다음 상세 화면에도 전달되도록 구성 |
| 테스트 접속 | 기본 집계 제외. 필요한 검토 기능은 일반 화면과 구분 |
| 첫 진입 | 최근 수집일을 보여주되, 오늘이 아니면 과거 자료임을 눈에 띄게 표시 |
| 일일 검토 | 어제·오늘·최근 수집일 바로가기. 범위를 선택한 뒤 적용 |
| 빈 날짜 | 0건을 표시하고 최신 수집일로 이동하는 경로 제공 |
| 데이터 미보유 | 0 대신 데이터 없음/집계 불가를 표시 |
| 오류 | 조회 실패를 별도로 표시. 오류를 0건으로 바꾸지 않음 |
| 시간 누락·부분 수집 | 마지막 수집 시각과 실제 범위를 표시. 트래픽이 없다는 이유만으로 장애 확정 금지 |

### 5.1 지표 정의

| 지표 | 최종 집계 정의 | 주의사항 |
|---|---|---|
| 전체 이벤트 | 선택 범위에 발생한 원본 이벤트 수 | 현재 `ingested_files.n_events` 합은 파일 집계이므로 날짜별 고유 이벤트 총수로 대체 금지 |
| 접속 세션 | 선택 범위에 시작한 고유 세션 수 | 출처/데이터셋 식별자를 포함한 복합키 사용 |
| 고유 IP | 선택 범위 세션의 서로 다른 유효 출발 IP 수 | 출발 IP가 실제 공격자 개인을 뜻하지 않음 |
| 로그인 시도 | 선택 범위 인증 성공 이벤트 + 실패 이벤트 수 | 세션 수·성공 플래그로 추정 금지 |
| 로그인 성공/실패 | 각 인증 이벤트의 결과별 수 | 성공 세션 수와 별도 지표 |
| 명령어 입력 | 선택 범위의 명령어 발생 시각 기준 입력 수 | 현재 초안의 ‘선택일 시작 세션 전체 명령어’와 다름. 전환 시 명칭·설명을 함께 변경 |
| 명령어 포함 세션 | 선택 범위 조건에 맞는 세션 중 입력이 있는 세션 수 | 전체 세션과 분석 대상 규모를 구분 |
| 탐지 세션 | 선택 범위·규칙 조건에 맞는 고유 세션 수 | 여러 규칙이 한 세션에 걸렸다고 세션 중복 합산 금지 |
| 시그니처 일치 수 | 규칙별 `n_hits` | 규칙에 따라 명령 줄 수 또는 완성 경로 수. 서로 같은 단위처럼 합산 금지 |
| 반복 접속 IP | 선택 범위에 2회 이상 접속한 IP | 당일 반복과 여러 날짜 재방문을 구분 |
| ML 분석 세션 | 실제 분석 실행 결과에 배정 정보가 있는 세션 수 | 미분석 세션을 노이즈로 취급하지 않음 |

## 6. Overview 상세 기획

### 6.1 정보 배치

참고 이미지처럼 어두운 배경에 경계가 분명한 카드 그리드를 사용한다. 큰 지도와 핵심 지표를 먼저 배치하고, 아래에서 인증·시간대·반복 행동을 조사하게 한다.

| 구역 | 구성 |
|---|---|
| 상단 | 화면명, 날짜/기간, 출처·프로토콜 필터, 수집 상태·마지막 갱신 |
| 핵심 지표 행 | 이벤트, 접속 세션, 고유 IP, 로그인 시도, 명령어. 데이터 준비 전에는 해당 카드 상태를 명시 |
| 중앙 왼쪽 | 공격 출발지 지도, 하루 재생·실시간 전환, 재생 시각·진행바 |
| 중앙 오른쪽 | SSH/Telnet 도넛, 반복 접속 IP 순위 |
| 하단 | 시간대별 변화, 계정·비밀번호 분포, 최근 접속/선택 IP 기록 |

작은 화면에서는 한 열 또는 두 열로 재배치한다. 지도를 보기 위해 주요 버튼이 화면 밖으로 밀리지 않게 한다.

### 6.2 공격 출발지 지도

- 국가별 세션 규모를 원 또는 색으로 표시한다. 초기 버전은 국가 단위 추정을 사용한다.
- 범례에 원의 크기/색이 뜻하는 값을 명시한다. 고유 IP 수와 세션 수를 혼동하지 않는다.
- 국가에 마우스를 올리면 추정 국가명, 세션 수, 고유 IP 수를 보여준다.
- 국가를 누르면 같은 범위의 출발 IP 목록과 접속 기록을 필터링한다. 선택 해제를 제공한다.
- IP 상세에서 해당 IP의 세션 이력을 열 수 있어야 한다.
- 위치를 알 수 없는 접속은 지도 밖의 ‘위치 미상’ 수치와 목록에 포함한다.
- 국가 대표점은 실제 서버 좌표나 공격자의 물리 위치가 아니다. GeoIP 자료 기준과 갱신 상태를 표시한다.
- 실제 근거가 없는 공격 경로·수집 서버 좌표·가상 점을 만들지 않는다.

### 6.3 하루 빠른 재생

| 기능 | 동작 |
|---|---|
| 재생 대상 | 선택한 하루와 필터에 해당하는 실제 접속 세션 |
| 시간 기준 | 세션 시작 시각. 인증·명령어 개별 이벤트 재생과 구분 |
| 재생 속도 | 하루를 30/60/120초로 압축하는 선택지 |
| 조작 | 시작, 일시정지, 처음부터, 전체 보기, 시각 슬라이더 |
| 표시 | 재생 중인 KST 시각, 현재까지의 세션 수, 누적 국가·IP 분포 |
| 종료 | 선택일 전체 기록으로 마무리하고 재생 완료 표시 |
| 빈 범위 | 데이터 없음 표시. 가상 접속을 만들지 않음 |

재생 중 지도·목록은 재생 시점까지의 값으로 움직인다. 상단 일일 통계가 하루 전체 값이라면 ‘하루 전체’임을 명시한다. 화면이 서로 다른 범위를 보여주면서 같은 수치처럼 보이면 안 된다.

### 6.4 실시간 모드

‘실시간’은 실제 수집 데이터가 갱신되는 상태를 뜻한다. 버튼만 있어서는 완성으로 보지 않는다.

1. 수집기 → 로그/DB 반영 → 대시보드 조회 경로가 연결되어야 한다.
2. 새 세션이 들어오면 지도·목록·통계가 갱신되어야 한다.
3. 최근 24시간 또는 오늘 중 어느 범위를 보여주는지 명시한다. **초기 권장안은 오늘 00:00부터 현재까지**다.
4. 마지막 이벤트 시각, 마지막 조회 시각, 연결 상태를 구분한다.
5. 새 데이터가 없는 대기 상태와 수집 연결 실패를 구분한다. 조용하다는 이유만으로 장애를 단정하지 않는다.
6. 과거 사본에서는 ‘보관 데이터·실시간 수집 미연결’로 안내한다. 과거 접속을 현재 접속처럼 표시하지 않는다.

현재 초안의 10초 DB 재조회는 조회 기능만 구현한 상태다. 원본 수집 파이프라인 연결은 별도 작업이다.

### 6.5 인증·계정·비밀번호

| 카드/차트 | 내용 |
|---|---|
| 인증 시도 현황 | 전체 시도, 성공, 실패 및 시간대별 변화 |
| 계정 TOP N | 시도된 사용자명별 이벤트 수. 빈 사용자명도 구분 |
| 비밀번호 TOP N | 시도된 비밀번호별 이벤트 수. 빈 비밀번호도 구분 |
| 계정·비밀번호 조합 | 반복된 조합과 횟수. 필요 시 상세 패널에서 제공 |
| 관련 IP·세션 | 항목 선택 시 관련 접속으로 이동 |

전체 시도 통계는 원본 인증 이벤트가 있어야 한다. 데이터가 없으면 현재처럼 ‘저장된 성공 계정/비밀번호’로 따로 표시하고, 전체 시도 분포와 혼합하지 않는다. 일부 로그만 연결했다면 인증 통계의 실제 범위를 설명한다.

비밀번호는 허니팟에 입력된 문자열을 보여주는 기능이다. 원문 표시/가림 선택은 상세 설계에서 정한다. 외부 공개 운영을 하게 되면 관리자 조회 범위와 원문 표시 정책을 별도로 정한다.

### 6.6 반복 IP·프로토콜·최근 기록

| 정보 | 표시 항목과 연결 |
|---|---|
| 반복 접속 IP TOP 10 | IP, 추정 국가, 접속 수, 최초/최근 접속, 프로토콜. 클릭하면 해당 IP의 전체 접속 이력 |
| 재방문 IP | 기간 내 접속 일수, 날짜별 횟수. 당일 반복 접속과 별도 표시 |
| 프로토콜 도넛 | SSH/Telnet/미상별 세션 수·비율, 중앙 전체 수. 클릭 시 같은 조건으로 필터 |
| 시간대별 추이 | KST 시간별 세션 수. 인증·명령어는 실제 이벤트 데이터 확보 후 선택 지표로 추가 |
| 최근 접속 | 시각, 출처·센서, IP, 추정 국가, 프로토콜, 인증/명령어 요약. 세션 상세로 이동 |

도넛의 분모는 현재 필터의 전체 세션이다. 미상 프로토콜을 숨겨서 SSH/Telnet 비율을 부풀리지 않는다.

## 7. Sessions와 IP 상세

### 7.1 세션 목록

필수 필터: 날짜/기간, 출처·센서, 프로토콜, IP, 명령어 유무. 인증 이벤트 확보 후 성공/실패 조건을 추가한다. IP는 정확히 일치하는 검색과 부분 검색을 구분한다.

필수 열: 출처, 세션 ID, 시작/종료, IP, 추정 국가, 프로토콜, 인증 요약, 명령어 수, 탐지 유무, ML 분석 상태. 목록에는 페이지 이동·정렬·필터 초기화를 제공한다.

### 7.2 세션 상세

- 접속 기본 정보와 데이터 출처.
- 원본 인증 시도 타임라인. 없으면 요약만 존재함을 명시.
- 입력 순서와 원본 시각을 보존한 명령어 흐름.
- 실패 명령어 조각·다운로드 관측은 입력 명령어와 구분.
- 한국어 시그니처와 구체적인 근거 명령어/단계.
- ML 배정 결과와 해당 군집/패턴으로 이동.
- 같은 IP의 다른 세션으로 이동.

### 7.3 IP 상세

동일 IP의 선택 기간 내 접속 수·접속 일수, 시간대별 변화, 출처·프로토콜 분포, 관련 계정·탐지·ML 군집 및 세션 목록을 보여준다. 같은 IP라고 같은 개인·공격 조직이라고 단정하지 않는다.

## 8. Detection

| 영역 | 필수 내용 |
|---|---|
| 규칙 목록 | 한국어 이름을 중심으로 코드·유형·단계 표시 |
| 요약 통계 | 탐지 고유 세션 수, 규칙별 일치 수 및 단위 |
| 상세 | 규칙 설명, 실제 일치 명령어, 명령어 인덱스, 시각 |
| 시퀀스 근거 | 다운로드→권한→실행 등 연결된 단계와 대상 파일 |
| 교차 이동 | 해당 세션, IP, 연결된 ML 결과 |
| 결과 기준 | 분석 시점, 규칙 버전, 저장 결과와 현재 재평가의 차이 |

‘탐지됨’은 규칙에 일치하는 관측이 있다는 뜻이다. 명령 입력만으로 실행 성공을 확정하지 않는다. 저장된 결과와 현재 규칙 재평가가 다르면 둘을 구분하고 차이를 표시한다.

## 9. ML Analysis

### 9.1 군집 그림

- 기존 실제 군집 배정 결과를 색으로 사용한다. 노이즈는 별도 색상으로 표시한다.
- 동일 정규화 패턴이 겹치면 묶고, 원 크기와 세션 수 관계를 범례로 설명한다.
- 군집 선택 강조, 패턴 선택, 멤버 세션 목록, 세션 상세 연결을 제공한다.
- 축은 시각화용 투영이며 거리·겹침은 근사치임을 표시한다.
- 군집이 예쁘게 보이도록 좌표를 임의로 배치하거나 분리하지 않는다.
- 분석 데이터나 군집이 바뀌면 이전 그림을 현재 결과처럼 보여주지 않는다.

### 9.2 군집 상세

프로토콜, 분석 실행 식별자/시각, 군집 번호, 세션 수, 고유 IP 수, 활동 기간, 대표 정규화 명령어 흐름, 시그니처 분포와 실제 멤버를 보여준다. 행동 해석은 관측 사실과 추정을 구분한다.

미분석, 분석 제외, 노이즈는 서로 다른 상태다. SSH 모델이 없는 자료에 Telnet 군집을 붙이지 않는다. 서로 다른 학습 실행의 ‘군집 0’을 같은 군집으로 합치지 않는다.

신규 패턴 후보 목록은 후속 기능으로 둔다. 후보/이상 점수가 곧 악성 확정이나 위험 확률은 아니다.

## 10. 데이터 통합과 수집 계획

### 10.1 기존 DB와 시드니 DB를 함께 보는 권장 방식

원본 두 개를 유지하고 **대시보드용 통합 DB 또는 조회 계층**을 별도로 만든다. 아직 어느 방식을 최종 선택한 것은 아니다.

1. 기존 `cowrie-logs`의 실제 수집 위치·기간·센서를 확인한다.
2. 두 DB의 출처·세션·원본 로그 중복 여부를 점검한다.
3. 데이터셋 식별자와 원래 출처를 보존한다. 다른 데이터셋의 같은 세션 ID가 충돌하지 않게 한다.
4. 동일 자료의 중복 사본과 실제 반복 접속을 구분한다.
5. 시그니처와 ML의 분석 버전·실행 단위를 보존한다.
6. 전체/출처별 필터와 합산 지표를 제공한다.
7. 통합 전후 세션·이벤트·분석 결과 수와 제외 수가 일치하는지 검증한다.

기존 DB의 ML 미분석 세션은 미분석으로 남긴다. 통합 데이터 재학습은 별도 작업이며 통합 조회를 위해 반드시 먼저 할 필요는 없다.

### 10.2 추가로 필요한 데이터

| 데이터 | 최소 필드 | 필요한 기능 |
|---|---|---|
| 원본 이벤트 | 출처·센서, 세션, 이벤트 시각·유형, 이벤트 식별/중복 판별 정보 | 정확한 이벤트 수·발생 시각 기준 추이 |
| 인증 이벤트 | 위 정보 + 계정, 비밀번호, 성공/실패 | 로그인 시도·계정·비밀번호 분포 |
| 접속 이벤트/세션 | IP, 프로토콜, 접속 시각, 세션 키 | 지도, 재생, 반복 IP, 실시간 신규 접속 |
| GeoIP 조회 자료 | IP 범위/조회 결과, 국가·좌표 단위, 자료 기준 | 추정 국가 지도·위치 미상 분리 |
| 분석 메타데이터 | 규칙 버전, 분석 실행 식별자·시각, 모델·정규화 버전 | 탐지·군집 결과의 기준 보존 |
| 수집 상태 | 센서별 마지막 수집·반영·조회 시각, 오류 상태 | 실제 실시간/지연/실패 구분 |

기존 분석 테이블은 조회 중심으로 재사용한다. 새 데이터 저장은 기존 팀원 스키마를 불필요하게 바꾸기보다 별도 테이블/보조 DB로 시작하는 방안을 검토한다.

화면 설계는 1~2단계에서 함께 진행할 수 있다. ‘실시간 완성’과 ‘전체 로그인 통계 완성’은 실제 데이터 연결 검증 전에는 완료로 표시하지 않는다.

### 11.1 첫 검토 버전의 합격 기준

- 관리자가 날짜를 선택해 해당 하루의 출발 국가·IP·반복 접속을 확인할 수 있다.
- 지도·순위·목록의 수치가 같은 필터를 사용한다.
- 하루 재생과 현재 데이터 확인이 시각적으로 구분된다.
- 세션·이벤트·인증 시도·명령어 수를 섞지 않는다.
- 실제 데이터가 없는 기능은 그 이유와 필요한 자료를 표시한다.
- IP/세션 → 명령어 → 탐지 근거/군집으로 이어진다.
- HTML로 들어올 수 있는 공격자 문자열을 안전한 텍스트로 표시한다.
- 읽기 전용 조회로 원본 데이터·분석 결과를 변경하지 않는다.
- 작은 화면에서도 주요 필터와 지도 조작이 가능하다.
